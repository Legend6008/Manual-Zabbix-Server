    Servicios del servidor Zabbix¶

    1. Introducción¶

    El servidor Zabbix utiliza diferentes servicios para recopilar, procesar y almacenar información de los equipos monitoreados. Cada servicio cumple una función específica dentro de la infraestructura.

    En este laboratorio, los principales servicios son Zabbix Server, la base de datos, Apache, el agente local y Tailscale.

    2. Servicios principales¶

    Servicio Función
    zabbix-server Procesa las métricas, ejecuta las comprobaciones y evalúa los triggers.
    mysql o mariadb Almacena la configuración, los datos recopilados y el historial de monitoreo.
    apache2 Permite acceder a la interfaz web de Zabbix desde un navegador.
    zabbix-agent o zabbix-agent2 Recopila métricas del servidor Ubuntu para su propio monitoreo.
    tailscaled Mantiene la conexión VPN de Tailscale con los demás equipos autorizados del laboratorio.

    Nota: los nombres de los servicios pueden variar según los paquetes instalados y la configuración del sistema.

    3. Verificación del estado de los servicios¶

    Para comprobar que los servicios estén funcionando, utilizamos el comando systemctl status.

    3.1. Zabbix Server¶

    sudo systemctl status zabbix-server

    Este servicio es el componente central de Zabbix. Recibe y procesa los datos de monitoreo, administra las comprobaciones y evalúa las condiciones de los triggers.

    El estado esperado es:

    Active: active (running)

    3.2. Base de datos¶

    sudo systemctl status mysql

    La base de datos almacena la información que necesita Zabbix para funcionar. Si el servicio no está disponible, el servidor puede presentar errores al iniciar o al guardar datos.

    3.3. Apache¶

    sudo systemctl status apache2

    Apache permite acceder a la interfaz web de Zabbix. Si el servicio está detenido o presenta errores de configuración, la página web puede dejar de estar disponible aunque el servidor Zabbix continúe ejecutándose.

    3.4. Agente local de Zabbix¶

    sudo systemctl status zabbix-agent

    El agente local permite recopilar métricas del propio servidor Ubuntu, como el uso de CPU, memoria y disco.

    Si se instaló Zabbix Agent 2, utilizar:

    sudo systemctl status zabbix-agent2

    3.5. Tailscale¶

    sudo systemctl status tailscaled

    Tailscale proporciona conectividad privada entre el servidor y los equipos del laboratorio. Esta conexión permite administrar el servidor y comunicar los agentes desde redes diferentes, siempre que los dispositivos estén autorizados y la configuración de red sea correcta.

    Para consultar el estado de la conexión VPN:

    tailscale status

    4. Administración de los servicios¶

    En Ubuntu Server, systemctl permite iniciar, detener, reiniciar y habilitar servicios.

    4.1. Iniciar un servicio¶

    sudo systemctl start zabbix-server

    Inicia el servicio Zabbix Server si se encuentra detenido.

    4.2. Detener un servicio¶

    sudo systemctl stop zabbix-server

    Detiene el servicio. Mientras permanezca detenido, Zabbix Server no podrá realizar sus tareas de monitoreo.

    4.3. Reiniciar un servicio¶

    sudo systemctl restart zabbix-server

    Detiene y vuelve a iniciar el servicio. Puede utilizarse después de modificar ciertos parámetros de configuración.

    4.4. Habilitar el inicio automático¶

    sudo systemctl enable zabbix-server

    Configura el servicio para que se inicie automáticamente durante el arranque del sistema operativo.

    Para habilitar Apache, por ejemplo:

    sudo systemctl enable apache2

    Precaución: antes de reiniciar o detener servicios en un entorno de producción, considerar el impacto sobre el monitoreo y los equipos administrados.

    5. Consulta de registros y diagnóstico¶

    Cuando un servicio presenta problemas, los registros permiten identificar errores de configuración, fallos de conexión o dificultades para acceder a la base de datos.

    5.1. Consultar los últimos registros de Zabbix Server¶

    sudo journalctl -u zabbix-server -n 50 --no-pager

    Muestra las últimas 50 entradas disponibles en el registro del servicio, sin abrir un visor interactivo.

    5.2. Seguir los registros en tiempo real¶

    sudo journalctl -u zabbix-server -f

    Permite observar nuevos mensajes mientras se generan. Para salir, presionar Ctrl + C.

    5.3. Revisar el archivo de registro de Zabbix¶

    En una instalación habitual, los registros del servidor se encuentran en:

    /var/log/zabbix/zabbix_server.log

    Para visualizar las últimas líneas:

    sudo tail -n 50 /var/log/zabbix/zabbix_server.log

    La ubicación exacta depende del parámetro LogFile definido en /etc/zabbix/zabbix_server.conf.

    6. Puertos de comunicación¶

    Los puertos utilizados dependen de los componentes instalados y del tipo de comprobación configurada.

    Puerto TCP Función
    80 Acceso HTTP a la interfaz web, si está habilitado.
    443 Acceso HTTPS a la interfaz web, si está habilitado.
    10050 Puerto habitual de escucha del agente Zabbix para comprobaciones pasivas.
    10051 Puerto habitual del servidor Zabbix para recibir conexiones de agentes activos y otras comunicaciones compatibles.

    En este laboratorio, Tailscale permite establecer comunicación privada entre los equipos. Las reglas del firewall deben limitar el acceso a los puertos según las necesidades reales de monitoreo.

    No es necesario exponer todos los puertos a Internet. Por ejemplo, si un agente funciona exclusivamente mediante comprobaciones activas, normalmente no necesita aceptar conexiones entrantes en el puerto 10050.

    7. Comprobación general del servidor¶

    Para realizar una revisión inicial, ejecutar:

    sudo systemctl status zabbix-server
sudo systemctl status apache2
sudo systemctl status tailscaled
tailscale status

    Consultar también el estado de la base de datos y del agente local según los nombres de servicio instalados.

    La revisión permite detectar servicios detenidos y problemas básicos de conectividad. Sin embargo, que los servicios aparezcan como activos no garantiza por sí solo que Zabbix esté recopilando métricas correctamente. También es necesario verificar la interfaz web, los datos recientes y el estado de los hosts.
